# 调研笔记：Iteration（迭代）→ Evolve（进化）

日期：2026-08-10；只读取证，未写任何 mod 代码。

## 结论速览

- 用户所说“迭代”= 塔2 故障机器人（Defect）Uncommon Power 卡 **Iteration**（游戏内 zhs 官方译名“迭代”）；“进化”= 塔1 铁甲战士（Ironclad）Uncommon Power 卡 **Evolve**。
- 两张卡形状完全一致：1 费、Power、Uncommon、TargetType.Self、打出流程同为“动画 + `PowerCmd.Apply<Power>`”。
- 唯一机制差异：Iteration 是**每回合第一次**抽到状态牌时抽 2 张（升级 3）；Evolve 是**每次**抽到状态牌时抽 1 张（升级 2）。差异集中在 `IterationPower.AfterCardDrawn` 的 `num <= 1` 限制与 `CanonicalVars` 数值。
- 107（v0.107.1，`refs/decompiled-107`）与 110（v0.110.1，`STS2 Source Code`）的 `Iteration.cs` / `IterationPower.cs` **逐行一致**，依赖 API 签名一致 → **单一 DLL 无需条件编译即可同时适配 107/110**。

## 塔2 Iteration（迭代，107/110 反编译实证）

- 类：`MegaCrit.Sts2.Core.Models.Cards.Iteration`；本地化键 `ITERATION.title/.description`（15 语言）。
- `CanonicalVars = PowerVar<IterationPower>(2m)`；构造 `base(1, CardType.Power, CardRarity.Uncommon, TargetType.Self)`。
- OnPlay：`CreatureCmd.TriggerAnim(..., "PowerUp", ...)` + `PowerCmd.Apply<IterationPower>(choiceContext, Owner.Creature, DynamicVars["IterationPower"].BaseValue, Owner.Creature, this)`。
- OnUpgrade：`DynamicVars["IterationPower"].UpgradeValueBy(1m)`（2→3）。
- `IterationPower`（`MegaCrit.Sts2.Core.Models.Powers.IterationPower`）：`PowerType.Buff`、`PowerStackType.Counter`。
- AfterCardDrawn：本人抽到 `CardType.Status` 时，统计 `CombatManager.History` 中本回合本人抽到 Status 的次数 `num`，`num <= 1` 才 `Flash()` + `CardPileCmd.Draw(choiceContext, Amount, Owner.Player)`（即每回合至多触发一次）。
- 全库引用：仅 `AbstractModelSubtypes` 类型注册、Iteration 卡（CanonicalVars/OnPlay/OnUpgrade）与自身——**IterationPower 为 Iteration 专属**，patch 不影响其他卡。
- 卡池：`DefectCardPool` 107 第 75 行、110 第 77 行均含 `ModelDb.Card<Iteration>()`（110 池内新增了其他卡导致行号后移）。
- 资源：pck 内存在 `defect/iteration.png`（图集区域 250×190）与 `iteration_power.png`（64×64 区域）。

## 塔1 Evolve（进化，本地正版 jar 实证 + 官方 wiki 佐证）

- 类：`com/megacrit/cardcrawl/cards/red/Evolve.class`；Power：`com/megacrit/cardcrawl/powers/EvolvePower.class`。
- Uncommon Power，1 费，目标自身；升级**不改费用**，数值 1→2。
- 英文卡面：`Whenever you draw a Status card, draw !M! card.`（升级 `...cards.`）；简中：`每当你抽到一张 状态牌 时，抽 !M! 张牌。`
- 14 语言官方文本已提取（zhs/zht/eng/jpn/kor/spa/ptb/fra/deu/rus/ita/pol/tha/tur；STS2 另有 esp 目录，内容同 spa——系列惯例 spa/esp 各写一份）。
- 卡图：`images/1024Portraits/red/power/evolve.png`（500×380，可 2× LANCZOS 放大为塔2 的 1000×760 + 250×190）；另有 beta 旧版 `images/1024PortraitsBeta/red/power/evolve.png`。
- Buff 图标：`powers/powers.png` 图集，`128/evolve` 条目 xy(100,838) size(80,91) orig(128,128) offset(25,18)；`48/evolve` 条目实现时按 atlas 提取。

## 塔2 相关 API（反编译实证，107/110 一致）

- `CardPileCmd.Draw(PlayerChoiceContext, decimal count, Player player, bool fromHandDraw = false)`：107 第 798 行、110 第 882 行，签名一致。
- `Hook.AfterCardDrawn(ICombatState, PlayerChoiceContext, CardModel, bool)`：逐张卡触发 `model.AfterCardDrawn(...)`（CardPileCmd.Draw 内部调用），107/110 一致。
- `PowerModel.AfterCardDrawn(PlayerChoiceContext, CardModel, bool)`：virtual，107/110 签名一致。
- `CardType.Status`：107/110 枚举一致。
- 文本 getter（整卡替换用）：`CardModel.TitleLocString` / `Description`；`PowerModel.Description` / `SmartDescription` / `TitleLocString`（继承）。
- 图标 getter（整卡替换用）：`PowerModel.PackedIconPath` / `IconPath` / `Icon` / `ResolvedBigIconPath` / `BigIcon`（系列 PhantomKiller/CorpseExplosion 已有完整 patch 先例）。

## 实现要点（规划级，未写代码）

1. patch `Iteration.CanonicalVars`：`PowerVar<IterationPower>(2m)` → `(1m)`；OnUpgrade 保持 +1，自动得 1/2。
2. patch `IterationPower.AfterCardDrawn`：去掉 `num <= 1` 限制，保留 Flash + Draw(Amount)。
3. 整卡替换扩展：文本键 `RE_EVOLVE.*` / `RE_EVOLVE_POWER.*`、卡图三 getter、Buff 图标 getter。
4. 守卫：Iteration 形状（Power/Self/1 费/PowerVar 值 2）+ IterationPower.AfterCardDrawn 签名 + ModLoaded API 存在性检查；不符则补丁自动失效并记日志。
5. 备用：若实机数值未刷新，补 `CardModel._dynamicVars` 缓存清理（RevertAnthony `ClearAllCanonicalCaches` 先例）。

## 版本兼容结论

- Iteration 本体与 IterationPower 107/110 零差异；本 mod 所需全部 API 签名一致，**单一 DLL 无需条件编译或反射分派**。
- 沿用系列“形状守卫 + 存在性检查 + 最小补丁面”策略：未来 beta 若改动 Iteration 形状或 hook 签名，补丁自动失效而非破坏游戏；若移除/重命名类，`ModLoaded` 降级跳过并记日志。
- 建议 `min_game_version = 0.107.1`（同时覆盖 107/110），不做分支判断、不锁版本号。
- 本地化键沿用系列防冲突前缀：`RE_EVOLVE.*` / `RE_EVOLVE_POWER.*`。
