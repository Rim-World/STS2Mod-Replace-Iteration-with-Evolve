## 目标

把塔2 故障机器人（Defect）Uncommon Power 卡“迭代”（Iteration）替换为塔1 铁甲战士（Ironclad）Uncommon Power 卡“进化”（Evolve）的效果：

- 塔2 迭代：1 费，打出获得迭代 Buff；**每回合第一次**抽到状态牌时，抽 2 张牌（升级 3 张）。
- 塔1 进化：1 费，打出获得进化 Buff；**每次**抽到状态牌时，抽 1 张牌（升级 2 张）。

两者类型、费用、稀有度、目标、打出流程完全一致；唯一机制差异是“每回合一次”限制与抽牌数值（2/3 vs 1/2）。用户已拍板：整卡替换（卡名“进化”、卡面文案、卡图、Buff 名/图标一并换成塔1 进化）+ 保留塔1 数值（基础 1、升级 2）。

## 机制差异源码定位（110 反编译）

`MegaCrit.Sts2.Core.Models.Powers.IterationPower.AfterCardDrawn`：

```csharp
if (card.Owner.Creature == base.Owner && card.Type == CardType.Status)
{
    int num = CombatManager.Instance.History.Entries.OfType<CardDrawnEntry>()
        .Count(e => e.HappenedThisTurn(base.CombatState) && e.Actor == base.Owner && e.Card.Type == CardType.Status);
    if (num <= 1)   // ← 每回合第一次的限制来源
    {
        Flash();
        await CardPileCmd.Draw(choiceContext, base.Amount, base.Owner.Player);
    }
}
```

删除 `num <= 1` 条件即得塔1“每次抽到状态牌都触发”的语义；额外抽牌同样走 `CardPileCmd.Draw`，抽到状态牌会连锁再次触发，与塔1 一致。

## 107/110 兼容性结论（已比对，无需条件编译）

- `Iteration.cs`、`IterationPower.cs` 在 107（`refs/decompiled-107`）与 110（`STS2 Source Code`）**逐行一致**。
- 依赖 API 签名一致：`CardPileCmd.Draw(PlayerChoiceContext, decimal, Player, bool)`、`Hook.AfterCardDrawn(ICombatState, PlayerChoiceContext, CardModel, bool)`、`CardType.Status`、`PowerCmd.Apply<T>`、`PowerModel.AfterCardDrawn(PlayerChoiceContext, CardModel, bool)`。
- `DefectCardPool` 107/110 均含 `ModelDb.Card<Iteration>()`。
- 因此**单一 DLL 无需反射分派或版本分支即可同时适配 107/110**（与 Scavenge→Recycle 同一结论）。

## 实现方案（复用 RecycleReplacementMod v1.0 骨架）

### 新项目

- 位置：`src/EvolveReplacementMod/`（沿用系列仓库，不新建仓库）。
- 工程：`Godot.NET.Sdk/4.5.1` + `net9.0`，引用本机 `sts2.dll` / `0Harmony.dll`，拷贝 `build.ps1` / `export_presets.cfg` / `project.godot` 模板并改命名。
- manifest：`EvolveReplacementMod.json`，`min_game_version = "0.107.1"`，`affects_gameplay: true`，`dependencies: []`。

### 核心补丁（必选，全部带 `IsReplaceIterationEnabled` + 形状守卫）

1. `Iteration.CanonicalVars` getter：`PowerVar<IterationPower>(2m)` → `PowerVar<IterationPower>(1m)`；升级保持 +1，自动得到 1/2 的塔1 数值。
2. `IterationPower.AfterCardDrawn` Prefix（整体替换）：保留“本人抽到 Status → Flash → `CardPileCmd.Draw(choiceContext, Amount, Owner.Player)`”，删除本回合次数限制。

备用（若实机发现数值仍为 2/3）：`CardModel.DynamicVars` 或 `_dynamicVars` 缓存未随 `CanonicalVars` 刷新时，追加缓存清理补丁（参考 RevertAnthony `ClearAllCanonicalCaches`）。

### 整卡替换扩展补丁（用户已拍板启用）

3. `CardModel.TitleLocString` / `Description` getter：切到 `RE_EVOLVE.title` / `RE_EVOLVE.description`。
4. `PowerModel.Description` / `SmartDescription` getter：切到 `RE_EVOLVE_POWER.*`（Buff 名“进化”）；标题键 `RE_EVOLVE_POWER.title`。
5. `CardModel.Portrait` / `PortraitPath` / `PortraitPngPath`：指向 pck 内塔1 Evolve 卡图（1000×760 + 250×190），DLL 内嵌兜底。
6. `PowerModel.PackedIconPath` / `ResolvedBigIconPath`（及 Icon/BigIcon）：指向塔1 EvolvePower 图标（64×64 + 256×256）。

### 形状守卫与未来兼容

> 2026-08-11 用户要求移除：以下形状守卫与 API 检测已从代码中删除，补丁固定生效；本节保留作为历史决策记录。

- `IterationShapeGuard`：读取 `Iteration` 构造器写入的私有字段（`Type`、`TargetType`、`CanonicalEnergyCost`、`CanonicalVars` 含 `PowerVar<IterationPower>` 且值 2），要求 Power / Self / 1 费；不符时 `IsReplaceIterationEnabled` 恒 false，全部补丁自动失效。
- `IterationPowerShapeGuard`：确认 `AfterCardDrawn` 方法存在且签名匹配；若未来版本改动 hook 签名，补丁自动失效而非崩溃。
- `ModLoaded` 做 API 存在性检查（`Iteration`、`IterationPower`、`CardPileCmd.Draw`、`Hook.AfterCardDrawn`、`PowerCmd.Apply`），缺失则跳过补丁并记日志。
- 不硬编码版本号、不做分支判断；`min_game_version` 仅作最低门槛。
- 已知边界：IterationPower 全库目前仅 Iteration 使用（类型注册 + 卡牌自身）；若未来其他卡/遗物也应用 IterationPower，本 mod 会同样按“进化”语义触发，计划中记为已知风险。

## 风险与难点

1. **数值缓存**：`CanonicalVars` 改动后若 `DynamicVars` 缓存未刷新，实机可能仍显示/打出 2/3；备用补丁为清理 `CardModel` 的 `_dynamicVars` 缓存（系列先例 RevertAnthony）。
2. **连锁触发**：每次抽到状态牌都额外抽牌，若连续抽到状态牌会连锁（塔1 同款语义）；需在实机确认无死循环/异常卡死（塔2 抽牌堆有上限，风险低）。
3. **状态牌判定**：塔2 `CardType.Status` 与塔1 Status 语义等价（Wound/Dazed 等）；`fromHandDraw` 参数原版未使用，保持一致。
4. **Buff 文本动态变量**：`ITERATION_POWER.smartDescription` 的 `{Amount:...}` 语法需按塔2 格式重写塔1 EvolvePower 描述（系列 PhantomKiller 已有成熟做法）。
5. **图鉴热路径**：getter 补丁保持 try/catch 兜底、卡图走小图（250×190）路径，避免图鉴滚动闪动（系列已定案）。
6. **其他 mod 键冲突**：本地化键用 `RE_EVOLVE.*` 专属前缀，防 CustomCardBalance 等新增同名卡覆盖。
