# 001 总体设计：迭代 → 进化整卡替换（EvolveReplacementMod）

- 版本：1.0
- 最后更新：2026-11-01
- 依据：`9.SRC/EvolveReplacementMod/` 现役源码（2026-08-15 构建）、`1.ADR/001-迭代替换为进化的整卡替换.md`、
  `3.DOCS/001-T-进化替换工程取证笔记.md`、`2.PLANS/001-G-迭代替换为进化施工计划.md`

> 本文只描述源码中确实存在的结构。无源码或文档支撑的内容标注「未记录」。

## 1. 设计目标

把《杀戮尖塔 2》故障机器人卡「迭代」（`MegaCrit.Sts2.Core.Models.Cards.Iteration`）整卡呈现为
《杀戮尖塔 1》铁甲战士卡「进化」（`Evolve`）：

- **行为**：触发条件由「每回合第一次抽到状态牌」改为「每次抽到状态牌」；数值由 2/3（基础/升级）
  改为塔1 的 1/2。
- **呈现**：卡名、卡面文本、卡图、Buff 名称、Buff 描述/智能描述、Buff 图标、Buff 大小图标全部换成塔1 进化。
- **不改卡池、不新增卡牌、不禁用原卡**：直接修改原卡模型与 Buff 模型，使历史存档中的卡牌一并生效。

非目标：

- 不复刻塔1 的其他隐藏行为（塔1 `EvolvePower` 只有「抽到状态牌抽牌」一条，本 mod 已完整覆盖）。
- 不提供运行时开关：`ModConfig.IsReplaceIterationEnabled` 恒为 `true`（见 ADR 2026-08-11 修订）。
- 不做版本分支：单一 DLL 同时面向 default 107 与 public beta 110（依据见 §7）。

## 2. 运行形态与加载链路

mod 以 `dll + pck + json 清单` 三件套安装到 `mods/EvolveReplacementMod/`：

```
游戏启动
  └─ 读取 mods/EvolveReplacementMod/EvolveReplacementMod.json（清单）
      ├─ id=EvolveReplacementMod，version=1.0，min_game_version=0.107.1
      ├─ has_dll=true，has_pck=true，affects_gameplay=true，dependencies=[]
      └─ 加载 EvolveReplacementMod.dll，触发 [ModInitializer("ModLoaded")]
          └─ ModEntry.ModLoaded()
              ├─ new Harmony("EvolveReplacementMod")
              └─ PatchAll(Assembly.GetExecutingAssembly())   ← 6 个文件、14 个补丁类一次性挂载
```

- `pck` 提供 `res://EvolveReplacementMod/` 下的 4 张图、`mod_image.png` 与 15 个语言 × 2 个 JSON，共 35 个条目。
- `dll` 额外内嵌 4 份 PNG（`assets/evolve_big.png`、`evolve_small.png`、`evolve_power_64.png`、
  `evolve_power_256.png`，见 `EvolveReplacementMod.csproj` 的 `EmbeddedResource`）作纹理兜底。

## 4. 补丁设计

14 个补丁全部以「实例类型 + `ModConfig.IsReplaceIterationEnabled`」为前置判断，不满足则返回原实现。

| # | 目标（Harmony 目标） | 类型 | 逻辑 | 失效影响 |
|---|---|---|---|---|
| 1 | `Iteration.CanonicalVars` getter | Postfix（无条件替换） | 返回 `new DynamicVar[]{ new PowerVar<IterationPower>(1m) }` | 数值回落 2/3 |
| 2 | `IterationPower.AfterCardDrawn` | Prefix，返回 `false` | 见下方伪代码；去掉了原版 `num <= 1` 的限制 | 恢复「每回合一次」语义 |
| 3 | `CardModel.TitleLocString` getter | Postfix | 仅 `Iteration` → `LocString("cards","RE_EVOLVE.title")` | 卡名回落「迭代」 |
| 4 | `CardModel.Description` getter | Postfix | 仅 `Iteration` → `LocString("cards","RE_EVOLVE.description")` | 卡面回落原版 |
| 5 | `CardModel.PortraitPngPath` getter | Prefix，返回 `false` | 仅 `Iteration` → `res://EvolveReplacementMod/images/card_portraits/big/evolve.png` | 卡图回落原版 |
| 6 | `CardModel.PortraitPath` getter | Prefix，返回 `false` | 同上路径 | 卡图回落原版 |
| 7 | `CardModel.Portrait` getter | Prefix，返回 `false` | `PortraitTextureLoader.Get()` | 卡图回落原版 |
| 8 | `PowerModel.Title` getter | Postfix | 仅 `IterationPower` → `RE_EVOLVE_POWER.title` | Buff 名回落「迭代」 |
| 9 | `PowerModel.Description` getter | Postfix | 仅 `IterationPower` → `RE_EVOLVE_POWER.description` | Buff 描述回落原版 |
| 10 | `PowerModel.SmartDescription` getter | Postfix | 仅 `IterationPower` → `RE_EVOLVE_POWER.smartDescription` | 智能描述回落原版 |
| 11 | `PowerModel.PackedIconPath` getter | Prefix，返回 `false` | 仅 `IterationPower` → `res://EvolveReplacementMod/images/powers/evolve.png` | Buff 图标回落原版 |
| 12 | `PowerModel.ResolvedBigIconPath` getter | Prefix，返回 `false` | 仅 `IterationPower` → `res://EvolveReplacementMod/images/powers/big/evolve.png` | 同上 |
| 13 | `PowerModel.Icon` getter | Prefix，返回 `false` | `PowerIconTextureLoader.Get64()` | 同上 |
| 14 | `PowerModel.BigIcon` getter | Prefix，返回 `false` | `PowerIconTextureLoader.Get256()` | 同上 |

补丁 2 的实际行为（`Patches/IterationPowerPatch.cs`）：

```csharp
if (card.Owner.Creature == power.Owner && card.Type == CardType.Status)
{
    Flash(power);                                              // 反射调用 PowerModel.Flash，失败静默
    await CardPileCmd.Draw(choiceContext, power.Amount, power.Owner.Player!);
}
```

设计取舍：

- **只改两处行为**：`Iteration` 的费用/类型/稀有度/目标与塔1 进化完全一致，故不补 `OnPlay` / `OnUpgrade`。
  升级仍走原版 `DynamicVars["IterationPower"].UpgradeValueBy(1m)`，基础值改 1 后自然得到升级 2。
- **整卡替换走 getter 而非换卡池**：不新增卡牌、不禁用旧卡，历史存档里的 `Iteration` 自动呈现为新样式。
- **模组专属本地化前缀 `RE_`**：键为 `RE_EVOLVE.title/.description` 与
  `RE_EVOLVE_POWER.title/.description/.smartDescription`，不覆盖原版 `ITERATION.*` / `ITERATION_POWER.*`，
  避免与第三方 mod（如 CustomCardBalance）同名键冲突。
- **文本用 Postfix 换 `LocString`、图用 Prefix 换返回值**：文本保留原 getter 的其它副作用；图直接短路，
  避免原版再查一次不存在的资源。
- **`Flash` 走反射**：`PowerModel.Flash` 为 `protected`，用 `AccessTools.Method` 取方法，取不到或抛异常只丢动画。

## 5. 数据流

```
卡牌/图鉴请求 CardModel 属性
  ├─ TitleLocString / Description ──Postfix──► LocString("cards", "RE_EVOLVE.*")
  ├─ PortraitPngPath / PortraitPath ─Prefix──► res://EvolveReplacementMod/images/card_portraits/big/evolve.png
  └─ Portrait ──────────────────────Prefix──► PortraitTextureLoader.Get()
                                               ├─ ResourceLoader.Load<Texture2D>(big/evolve.png)   ← pck
                                               └─ 失败 → 内嵌 assets.evolve_big.png → ImageTexture

战斗触发
  Hook.AfterCardDrawn ──► IterationPower.AfterCardDrawn ──Prefix──► 本人抽到 Status 即 Draw(Amount)
                          （原版 num<=1 限制已被整体替换；连锁抽到状态牌会继续触发，与塔1 一致）

Buff 面板
  ├─ Title / Description / SmartDescription ─Postfix─► RE_EVOLVE_POWER.*
  ├─ PackedIconPath / ResolvedBigIconPath ───Prefix──► res://…/images/powers/evolve.png、…/powers/big/evolve.png
  └─ Icon / BigIcon ─────────────────────────Prefix──► PowerIconTextureLoader.Get64() / Get256()
                                                        ├─ pck 资源
                                                        └─ 失败 → 内嵌 evolve_power_64/256.png
```

## 6. 异常处理

| 位置 | 处理 |
|---|---|
| `ModEntry.ModLoaded()` | 整体 `try/catch`；`PatchAll` 抛异常（游戏更新导致签名变化）时 `Log.Error` 并放弃挂载，mod 失效但游戏不崩 |
| `PortraitTextureLoader.Get()` | 两级 `try/catch`：pck 加载失败记 `Warn` 转内嵌；内嵌失败记 `Error`，返回 `null` |
| `PowerIconTextureLoader.Load()` | 同上，每档图标独立兜底，单档失败不影响另一档 |
| 补丁 2 的 `Flash()` | `try/catch` 吞掉反射异常（动画失败不影响抽牌效果） |
| 所有 getter 补丁 | 先判 `__instance is Iteration` / `is IterationPower`，非目标实例直接 `return true` 走原实现 |

- 纹理用 `_initialized` / `_texture` 静态字段缓存，避免图鉴滚动时重复解码。
- 未记录：日志文件落盘位置与日志等级配置由游戏侧决定，本 mod 只调用 `Log.Info/Warn/Error`。

## 7. 兼容性设计

| 维度 | 结论 | 依据 |
|---|---|---|
| 游戏版本 | 单 DLL 通吃 default 0.107.1 与 public beta 0.110.x | 两版 `Iteration.cs` / `IterationPower.cs` 反编译逐行一致，依赖 API 签名一致（见 001-T） |
| 版本判定 | 不做版本分支，`min_game_version=0.107.1` 仅作最低门槛 | `ModEntry` 无版本检查代码；`ModConfig` 恒 `true` |
| 语言 | 15 个语言目录：deu/eng/esp/fra/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht | 每个目录 `cards.json` + `powers.json`，键固定 2 + 3 条 |
| 第三方 mod | 低冲突：无新卡牌、无自定义 Power、无全局状态、`RE_` 专属键 | 源码结构；`IterationPower` 在全库仅为 `Iteration` 使用（001-T 取证） |
| 存档 | 开启即把历史记录中的「迭代」呈现为「进化」，关闭即恢复 | 直接改原卡/原 Power 模型，不写存档字段 |
| 依赖 | 无。不依赖 BaseLib / RitsuLib | 清单 `dependencies: []`；只引用游戏自带 `sts2.dll`、`0Harmony.dll` |

已知边界：`IterationPower` 是「迭代」专属 Power，若未来其他卡或遗物复用该 Power，本 mod 会同样按「进化」语义触发。
该风险由 ADR 001 记录，未做防呆（2026-08-11 已按用户要求移除形状守卫）。

## 9. 已知风险与后续

1. **实机验证缺失**：v0.1.0、v1.0 两轮都只做了静态验证（构建 0 警告 0 错误、DLL 符号校验、pck 条目数），
   连锁抽牌与 107 表现无实测记录。
2. **游戏更新破坏签名**：补丁全部按方法名 + getter 挂载，更新后签名变化会让 `PatchAll` 抛异常；
   已被 `try/catch` 兜住，但 mod 会整体失效，需每次版本更新做反编译比对。
3. **`assets/evolve_small.png` 未被代码引用**：`csproj` 把它内嵌进 DLL，但 `PortraitTextureLoader` 只读
   `evolve_big.png`，小图走 pck 的 `images/card_portraits/evolve.png`。属冗余资源，不影响运行，未改动代码。
4. **`IterationPower` 复用风险**：见 §7 已知边界。
